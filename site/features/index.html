Caddy の機能
トップ Caddy の機能 /healthz

ここに書いてあることは、リポジトリ直下の Caddyfile と対応しています。設定の全文と節ごとの解説は README にあります。

自動 HTTPS は、このデプロイでは使わない

Caddy は、公開できるホスト名でサイトを定義すると、証明書の取得と更新を自分で行います。それが自動 HTTPS です。訪問者のブラウザとサーバの間を、Caddy 自身が TLS で包みます。

Render の Web サービスでは、その役割は入口のプロキシが持ちます。ブラウザから Render までは HTTPS で、コンテナに届く時点では平文の HTTP です。コンテナの中で証明書を取りに行くと、待受が衝突したり、名前解決の対象がコンテナ自身になって失敗したりします。

  1. 1. ブラウザHTTPS
  2. 2. Render の入口TLS はここで終わる
  3. 3. Caddy平文 HTTP。ポートは PORT

そのため Caddyfile のグローバルオプションは auto_https off です。サイトアドレスも :{$PORT:8080} と、ホスト名ではなくポートだけにしています。コロンから始まるアドレスは全インターフェースの HTTP です。待ち受けは HTTP/1.1 だけにしています。TLS が無い HTTP/2 は使えず、ブラウザとの HTTP/2 は Render の入口が担当します。

逆プロキシは手元の Compose だけ

逆プロキシは、受け取ったリクエストを別のプロセスへ渡し、その応答をクライアントに返す動きです。アプリをインターネットに直接出さず、入口を 1 つにまとめられます。

この見本では /api/* だけを、Compose 内の api コンテナ（ポート 8080）へ渡します。設定は compose/proxy.caddy にあり、実行時にマウントします。Dockerfile はコピーしません。Render の無料枠はインスタンスを 1 つしか持てず、ディスクも付けられないので、公開先は静的サイトのコンテナだけにします。

下のボタンは GET /api/hello を呼びます。Compose では 2 台目の JSON が返り、単体コンテナではこのパスを配っていないので 404 になります。

まだ呼んでいません。

圧縮

encode zstd gzip は、応答の本文を圧縮します。クライアントが Accept-Encoding で示す方式から選び、q 値が同じなら先に書いた zstd を使います。gzip は、zstd を話さないクライアント向けのフォールバックです。

既定では本文が 512 バイト未満の応答は圧縮しません。/healthz の ok が平文のままなのはそのためです。圧縮した応答には Content-Length が付かず、Vary: Accept-Encoding が付きます。

curl -sD - -o /dev/null -H 'Accept-Encoding: gzip' http://127.0.0.1:8080/

ヘッダ

全応答に、内容の推測禁止（nosniff）、フレーム埋め込みの拒否、Referrer-Policy、Content-Security-Policy、Permissions-Policy を付けています。CSP の frame-ancestors が現在の埋め込み制御で、X-Frame-Options は古いクライアント向けの重ねがけです。

HSTS はブラウザに「このホストは以後 HTTPS で開け」と記憶させます。localhost に付けると手元の HTTP が開けなくなるので、ホストが localhost と 127.0.0.1 のときは付けません。Render のホスト名で届いた応答にだけ付きます。

HTML の Cache-Control は no-cache（保存してよいが、使う前に再検証する）です。CSS や JS や SVG は 1 日キャッシュします。ファイル名に内容ハッシュが無いので、immutable にはしていません。/healthz は no-store です。

廃止された X-XSS-Protection は付けていません。有効にすると、古いブラウザで別の不具合を招くことがあります。

アクセスログ

サイトブロックの log は、1 リクエストにつき 1 行の JSON を標準出力へ書きます。コンテナのログがそのまま記録になる、という形です。プロセスの起動メッセージも、グローバルオプション側で JSON にしています。

手前にプロキシがいるとき、ログに出るクライアントアドレスは訪問者ではなく入口のアドレスになることがあります。この見本ではそこは直しません。

ヘルスチェック

/healthz は 200 と本文 ok だけを返します。依存関係の問い合わせはしません。Render の healthCheckPath も同じパスです。

この見本は Caddy、Docker、Render の各名称を説明のために使っています。各プロジェクトの公式サイトではありません。
